# Scientist mode

The current release is **2.5**. See [baseline and Bayesian geometric distances](SCIENTIST_DISTANCE.md), [Explorer comparisons and approximate radius](SCIENTIST_COMPARISON_AND_RADIUS.md), and [query timing, cache and carbon-star handling](SCIENTIST_NETWORK_AND_CARBON.md). Earlier version-specific notes below describe the temperature model's development.

Launch `Main.py` and choose **Explorer** or **Scientist**. Explorer retains the existing simple interface and calculation pipeline. Scientist runs `Main_temperature.py`, which can also be launched directly. `WebMain_temperature.py` is the separate web variant (default port 65001); `WebMain.py` and the existing deployment configuration remain unchanged.

Future scientific-accuracy improvements belong in `Main_temperature.py` and its `temperature_*` helper modules. The launcher is in `app_launcher.py`. Keep Explorer's calculation behavior separate unless a change to that mode is specifically requested.

The implementation uses the two supplied September 17 specifications as design inputs, with the user's explicit isolation requirement taking precedence over the document's suggestion to modify Main.py. Experimental calculations, chart modules, logs and saved results have separate names. No original saved file is rewritten on startup or load.

## Using it

Version 2.2 adds the requested **approximate Explorer BP−RP fallback**, enabled by default. If neither an eligible Gaia temperature nor a supported scientific colour estimate is available, Scientist uses the existing Explorer formula and labels the result unvalidated and requiring review. This explicitly changes the earlier strict-unavailable behaviour at the user's request. It does not expand Casagrande's domain, invent a gravity measurement, or validate the old polynomial for carbon stars. The scientific result/status remains separately recorded. An available Gaia or supported scientific colour result is never displaced by this fallback.

The fallback uses intrinsic colour when available. If reddening is unavailable, it uses observed BP−RP with an explicit uncorrected-colour label. Existing Explorer branches and their raw-metallicity behaviour are retained separately from the scientific metallicity policy; the actual composition used is recorded. No formal uncertainty is fabricated. Any resulting classification remains approximate or unclassified. The fallback can be disabled in Temperature Settings, restoring strict scientific eligibility. Desktop single queries, bulk queries and the Scientist web variant share this policy; saved JSON includes the fallback setting, input colour, method and full-precision result. Explorer itself is unchanged.

Query an object as before. Immediately after the object identity, the results show Gaia temperature/source, BP−RP temperature/method, adopted temperature/source and selection reason/status. **Calculation details** expands catalogue temperatures and bounds, gravity, composition assumptions, sensitivity examples and recorded settings. The control works in Explain and Copy modes. Displayed temperatures are rounded to whole kelvin; machine-readable results retain full precision.

**Temperature Settings** controls the calibration, population hypothesis, composition input, metallicity vetting confirmation, blue-colour solar-composition cutoff, explicit zero-reddening assumption and adopted-source override. Overrides require a reason and can select only an eligible estimate, including an applicable ESP-HS estimate. Settings apply to subsequent single and bulk queries; rerun an object to change its adoption. A bulk run takes a settings snapshot so a subsequent settings change cannot mix policies within that run.

**Save** writes a text table plus a matching `.json` file under `saved_objects_temperature`. The JSON retains full precision, settings, catalogue temperatures, colour comparisons and analysis flags even if details or bulk columns were hidden. Both catalogue metallicity and requested/actually used composition are retained. Keep both files. **Load Saved Results** reads these JSON records or the original app's text tables without contacting services or recalculating. Old temperature, radius and classification values are retained in explicitly labelled legacy fields; unavailable new fields remain null.

The separate web app exposes the same calibration and assumption choices and saves the same versioned data. Loading saved results and advanced cluster charts are desktop features, as in this implementation's existing UI structure.

## Implemented calculation

- Both single and batch queries request GSP-Phot temperature, gravity, metallicity, extinction, bounds and fit metadata, plus individual BP/RP magnitudes, flux S/N and parallax error. The optional AP query also requests `teff_esphs`, `teff_esphs_uncertainty` (both K), `flags_esphs` and `spectraltype_esphs`. Missing AP rows or an AP query failure leave source photometry intact. Gaia identifiers remain exact strings, including in browser responses; ESP-HS flags preserve leading zeroes.
- Default colour method: Casagrande's DR3 BP−RP relation. Its full-precision coefficients and gravity-dependent colour limits were checked against the [author's implementation](https://raw.githubusercontent.com/casaluca/colte/main/colte.py). The colour domain is 0.20–2.00 for logg >3.2 and 0.20–2.55 otherwise. The app separately enforces conservative application limits logg 0–4.8 and Fe/H −3–0.6 and retains the 3600–9000 K temperature limit. The gravity boundary selects a domain, not a final luminosity class. The [paper](https://arxiv.org/pdf/2011.02517) supplies the fit scatter and narrower independent-validation interval (4000–6700 K); outside that interval is flagged.
- Optional Mucciarelli BP−RP calibration retains its separate dwarf/giant domains, coefficients and scatter from [Table 1](https://openaccess.inaf.it/bitstreams/1bc55391-09ff-4fbc-abc2-d2f88a909bdf/download). A supported redder dwarf falls back to the supplied approximate [Mamajek dwarf reference](https://www.pas.rochester.edu/~emamajek/EEM_dwarf_UBVIJHK_colors_Teff.txt) interpolation when the primary colour relation no longer applies. Its DR2 colour origin and approximate status remain visible. There is no special temperature switch at colour 1.8 and no extrapolation of either temperature calibration.
- Actual usable Gaia gravity is retained, including intermediate/subgiant values. Missing gravity bounds do not discard the central value; they trigger review and leave its uncertainty unknown. A final dwarf/giant classification is not a prerequisite. If gravity itself is missing, recorded dwarf/giant evidence can support labelled logg 4/2 assumptions; otherwise no eligible colour temperature is fabricated. Unsupported populations are excluded from the colour calibration.
- Solar composition is explicitly assumed by default; raw Gaia M/H is stored independently and used as Fe/H only on explicit request. Supplied metallicity retains its source and an explicit user vetting confirmation; provenance text alone cannot make it preferred evidence. For intrinsic BP−RP below the configurable default cutoff 0.35, the ordinary colour calculation uses solar composition and records why. This is an application screen, not a universal spectral boundary. It never changes the published Gaia temperature or permits extrapolation below colour 0.20.
- Gaia reddening is used when available; otherwise the existing NADC map is retained with unknown-error status. One chosen correction is subtracted once. Explicit zero reddening is provisional. C* uses **observed** colour and the reference helper's Riello tolerance. Missing S/N or quality inputs are unassessed. Shared Gaia inputs are disclosed rather than counted as independent validation.
- A single deterministic policy prefers eligible Gaia temperature, allows strong colour evidence to supersede a specific Gaia problem, and keeps unresolved conflicts provisional. The adopted value remains in `effective_temperature`, so classification and Wien wavelength use it consistently. No averaging hides a conflict.
- The quick red-dwarf screen remains a heuristic using intrinsic BP−RP >1.8 and estimated Johnson **Mv** >8.69, with warnings for uncertain inputs and brighter binaries. Failed selection does not establish a giant population. A measured logg ≤3 conflicting with dwarf evidence triggers review and disables automatic dwarf fallback. Valid overlapping Casagrande and approximate cool-dwarf estimates remain in calculation details; the approximate interpolation has no metallicity correction and no extrapolation beyond its reference points.
- The experimental Gaia-to-Johnson-V conversion was corrected to [ESA DR3 Table 5.9](https://gea.esac.esa.int/archive/documentation/GDR3/Data_processing/chap_cu5pho/cu5pho_sec_photSystem/cu5pho_ssec_photRelations.html): `V = G + 0.02704 - 0.01424*C + 0.2156*C² - 0.01426*C³`. It is not evaluated outside the published open interval −0.5 < C < 5. The stronger CMD screen uses the conservative application subset 0.2–2.5; far-red transformations stay uncertain.
- `10**(0.4*(4.67-MG))` remains available as **G-band Solar Brightness Ratio**. It is no longer used as bolometric luminosity. Radius stays unavailable without a vetted bolometric correction. The supplied bolometric helper is retained and tested separately; no correction grid is invented.
- Spectral charts retain total counts and separate estimated/tentative/approximate matrices. Hovering shows a cell's breakdown. CSV includes status matrices and source-level temperature provenance. CMD CSV also retains temperature/classification status.

## Uncertainty and limits

The Casagrande helper implements analytical covariance propagation with 55 K fit scatter and 20 K scale uncertainty. When all required errors are supplied, the app uses 2,048 deterministic Monte Carlo draws with asymmetric widths from available catalogue bounds, adding those same two terms. Those draws approximate marginal distributions; unprovided correlations are explicitly omitted. Draws outside calibration domains are rejected and counted, never clipped; if more than 5% are invalid, the interval is withheld. This is a conditional uncertainty, not a posterior fit or a total accuracy guarantee. Assumed gravity/composition and missing measured errors do not receive fabricated zero uncertainty: the propagated interval is unavailable, with sensitivity examples shown separately.

ESP-HS fields and flags were checked against the [DR3 AP data model](https://gea.esac.esa.int/archive/documentation/GDR3/Gaia_archive/chap_datamodel/sec_dm_astrophysical_parameter_tables/ssec_dm_astrophysical_parameters.html) and [ESP-HS processing documentation](https://gea.esac.esa.int/archive/documentation/GDR3/Data_analysis/chap_cu8par/sec_cu8par_apsis/ssec_cu8par_apsis_esphs.html). The app requires a finite 7000–50000 K temperature, G <17.65, an O/B/A catalogue tag and supported two-digit flags. First digit 0 means BP/RP+RVS; 1 means BP/RP only. Second digit 1–5 records tag confidence; 999 is invalid. Requiring grade 1 for a candidate without quality concerns is an application choice. Mode 0 uncertainties receive a review note for documented underestimation (factors 5–10), without invented rescaling. Missing/invalid errors or other confidence grades require review. An eligible GSP-Phot result is retained by default rather than replaced merely because ESP-HS exists or has a smaller uncertainty; disagreement is flagged. ESP-HS can supply an otherwise missing Gaia candidate, or be explicitly selected with a reason. Its solar-composition models and shared Gaia inputs are disclosed.

Quality messages identify failed BP or RP S/N, missing required information, failed C*, and bright-source concerns separately. Numerical colour estimates distinguish `conditional`, `approximate`, and `needs_review`; missing inputs give `unavailable`, and rejected calibration inputs give `outside_domain`. Approximate provenance remains recorded even when additional concerns require review.

The app uses explicit application screens, not calibrated reliability probabilities: BP and RP S/N ≥20; |C*| <3 sigma; Gaia interval fraction >5% for review; disagreement greater than max(300 K, 5% of the pair's mean). These are configurable. RUWE >1.4 prompts review without rejecting a temperature or declaring nonmembership. Simple inverse-parallax distance is withheld below S/N 5; stronger CMD support requires S/N ≥10. No Bayesian distance inference, membership model, mass/age fit, infrared crossmatch or bolometric correction grid is added.

GSP-Phot has model/extinction/systematic limitations even with narrow catalogue bounds; see [Gaia's validation discussion](https://gea.esac.esa.int/archive/documentation/GDR3/Data_analysis/chap_cu8par/sec_cu8par_apsis/ssec_cu8par_apsis_gspphot.html). The inherited HR classification rules remain estimates. The approximate cool-dwarf route must not be used alone for a secure M-subtype census. External benchmark validation is still needed before making scientific accuracy claims.

## Verification and illustrative output

Version 2.1 added input-driven eligibility, the blue-colour composition screen, optional ESP-HS and expandable details, following the supplied September 21 instructions. Version 2.2 adds the subsequently requested Explorer compatibility fallback. The regression suite includes 88 tests covering the original features, launcher, Scientist pipeline and all Explorer formula branches. Explorer's `Main.py` is unchanged by this update.

Missing-temperature diagnostics distinguish `query_failed`, `no_row`, and `retrieved` parameter-query states in single and bulk results. A successful source query does not imply that Gaia publishes a temperature or gravity for that object. The selection reason retains the individual Gaia and colour blockers instead of merely saying neither source is eligible. A CSTAR tag prompts review and withholds the ordinary-star colour calibration; it does not erase a separately available Gaia temperature or establish a definitive carbon-star classification.

A direct ESA synchronous query on September 21 for the latest reported source, `1542553623374596352`, returned G = 3.9576192, observed BP−RP = 2.593668, null GSP-Phot temperature and gravity in both `gaia_source` and `astrophysical_parameters`, null ESP-HS temperature, flags `90`, and tag `CSTAR`. This confirms missing catalogue parameters for that object, rather than a failed parameter query. Scientist cannot apply the ordinary colour calibration without usable gravity or supported assumptions. Since version 2.2 it can instead display the explicitly unvalidated Explorer fallback. Regression coverage reproduces these catalogue values with a controlled dust-map response; this is a software check, not validation of the fallback temperature's physical accuracy.

Tests use mocked remote responses, not a live cluster refresh. They cover numerical anchors and derivatives, parameter boundaries, conditional uncertainty and invalid draws, selection-policy branches and overrides, observed-colour C*, missing reddening, poor parallax, absent/failed AP queries, exact IDs, save/load round trips, classification consumers, separate histogram statuses and export. Native Tk checks exercise settings, both temperature displays, Copy mode, saved-result loading, bulk results and spectral chart generation. Web checks exercise page generation, query/setting dispatch, rows and saved data; they are not a browser-driven end-to-end test.
